# 社会工作服务板块演示原型设计方案

**日期：** 2026-07-24  
**状态：** 待用户审阅  
**目标产物：** 可交互、功能完整的静态 HTML 原型（`pc.html` + `h5.html`），用于业主演示  
**依据：** 《社会工作服务板块（pc+群众端）功能清单》及本轮设计确认  

---

## 1. 概述

在现有「金华市基层智治综合应用」中新增 **社会工作服务** 板块（PC 端嵌入现网系统壳）。群众端为 **新建 H5**。本阶段交付离线可运行、全量深交互的 HTML 演示原型，不接真实后端。

### 1.1 已锁定决策

| 项 | 结论 |
|----|------|
| 质量目标 | 相对旧原型整套推翻：视觉、交互、业务贴合、信息架构全面达标 |
| 交互深度 | 功能清单 **全量深交互** |
| 交付形态 | 单文件双端：`pc.html` + `h5.html` |
| 技术方案 | 领域数据核 + 双端 SPA 壳 + 共享 `localStorage` |
| PC 定位 | 现网系统壳；顶栏一级菜单插入「社会工作服务」；左侧仅展示本板块下级 |
| 跨端 | 同浏览器共享模拟数据，闭环可演示 |
| 组织 | 市 / 区县 / 乡镇 / 村社四级 + 本级可管、下级只读 |
| 省级模块 | 只读回流台账 + 模拟同步/刷新 |
| H5 底栏 | **首页 / 服务 / 我的** |
| H5 入口 | **全量业务入口在首页**；**服务 Tab 仅服务资源**（设施+力量） |
| UI | 中国政务后台风格（Ant Design / Element Plus）；PC 列表与抽屉严格对照现网截图 |

### 1.2 非目标

- 真实登录、网关、省级接口对接  
- 真实地图 SDK、文件二进制上传存储  
- 复杂富文本编辑器  
- 现网其它一级菜单业务页实现

```text
┌─────────────────────────────────────────────────────┐
│  领域数据层（localStorage）                          │
│  orgs / sessions / notices / activities / …         │
└──────────────────────┬──────────────────────────────┘
                       │ DataAPI（读写 + 组织/用户过滤）
       ┌───────────────┴───────────────┐
       ▼                               ▼
┌──────────────────┐         ┌──────────────────┐
│ pc.html          │         │ h5.html          │
│ 系统壳 + 侧栏    │         │ 手机框 + 三 Tab  │
│ 页面注册表 SPA   │         │ 页面注册表 SPA   │
│ 列表 / 右抽屉    │         │ 列表 / 详情/表单 │
└──────────────────┘         └──────────────────┘
```

**单文件内部分区（强制）：**

1. Design Tokens / CSS  
2. Seed + Storage  
3. DataAPI + 权限  
4. UI Kit（表格、抽屉、toast、步骤条等）  
5. 页面注册表 `Pages[route] = render`  
6. Shell  
7. `boot()`  

页面禁止绕过 DataAPI 直接裸读业务数组。

## 6. 领域数据模型

### 6.1 存储约定

| 项 | 约定 |
|----|------|
| 介质 | `localStorage` |
| 前缀 | `sws_v1_` |
| 初始化 | 首次自动写入种子；提供「重置演示数据」 |
| 会话 | `sws_v1_session_pc`、`sws_v1_session_h5` |

### 6.2 组织与账号

四级：`city` → `district` → `town` → `village`（金华示例数据）。

PC 演示角色至少包括：市级管理员、街道 **综合信息指挥室（中心）**、街道 **部门**（≥2）、社区管理员。  

H5：≥2 名绑定村社的居民。

### 6.3 统一字段

多数实体包含：`id, orgId, orgLevel, orgName, status, createdAt, updatedAt, createdBy`；需要范围控制时含 `scopeType, scopeOrgIds`。

### 6.4 实体清单

**省级回流（只读）：**  
`emerging_objects`, `emerging_party`, `emerging_governance`, `base_village`, `base_consult`, `base_lists`, `base_teams`  
（含 `source: "省级统建回流"`, `syncedAt`）

**信息公开：**  
`notices`, `activities`, `activity_signups`, `affairs`（三务类型 party/village/finance）, `service_items`

**人民建议：**  
`suggestion_inbox`, `collect_campaigns`, `suggestions`, `surveys`, `survey_answers`

**议事协商：**  
`topics`, `topic_comments`, `topic_votes`, `residents`

**服务资源：**  
`facilities`, `forces`

**帮扶：**  
`vulnerable_persons`, `aid_policies`, `foundations`, `assist_records`, `assist_applications`

统计类可由前端聚合，不强制落库。

### 6.5 组织权限与可见性

**PC：** 向下可见；仅本级可编辑/删除/上下架；下级只读；表格展示发布层级标签。  

**H5：**

| 规则类型 | 模块 |
|----------|------|
| 本级+上级已发布 | 通知、服务项目、设施、力量、救助政策、基金会 |
| 发布 scope 命中 | 活动、征集、评议、测评 |
| 仅本村社 | 三务、议题讨论与表决 |
| 仅本人 | 建议/帮扶进度与记录 |
| 不在 H5 | 归集、受理台账等纯 PC 能力 |

默认发布范围：`all_children`（自动下发下级）；三务/议事强制村社范围。

### 6.6 跨端写路径

- H5 活动报名 → PC 报名名单  
- H5 建议提交 → PC 受理 → H5 进度  
- H5 讨论/表决 → PC 结果  
- H5 帮扶申请 → 乡镇中心受理指派 → 部门审核 → H5 步骤条更新  
- PC 发布内容 → H5 按规则可见

## 7. 状态机与关键流程

### 7.1 通用

- 信息公开类（公告/三务/服务项目）：`draft` → `published` ↔ `offline`，可删除  
- 活动：同上，可 `ended`；报名 `submitted`  
- 征集：`draft` → `open` → `closed`  
- 建议办理：`submitted` → `accepted` → `processing` → `done`，或 `rejected`  
- 归集线索：`pending` → `accepted` / `rejected` / `closed`  
- 问卷：`draft` → `open` → `closed`；答案一人一卷  
- 议题：`draft` → `discussing` → `voting` → `closed`  
- 资源/政策：`published` ↔ `offline`  
- 省级：仅展示 + 同步刷新 `syncedAt`  

### 7.2 帮扶申请（强制业务规则）

**流程：提交 → 受理 → 指派 → 审核（办结）**

```text
群众提交
  → 固定推送至「乡镇中心（综合信息指挥室）」
      ├─ 不予受理（必填原因）→ 终态 rejected
      └─ 受理并指派（必填指派说明 + 指派乡镇部门）→ assigned
            → 乡镇部门
                ├─ 审核通过 → completed（即办结，无单独办结按钮）
                └─ 退回（必填原因）→ returned（回中心，可重新指派）
```

| status | 含义 |
|--------|------|
| `submitted` | 已提交，待中心受理 |
| `rejected` | 中心不予受理（终态） |
| `assigned` | 已受理并已指派，待部门审核 |
| `returned` | 部门退回中心 |
| `completed` | 部门审核通过=办结（终态） |

**H5 进度 UI：** 仿政务办件卡片——横向四步点（提交 / 受理 / 指派 / 审核）；完成/当前绿、未到灰、失败红；展示办理单位、进度说明、业务申报时间；**不展示咨询电话**。

## 8. UI 风格规范（强制）

### 8.1 整体

- 参考 **Ant Design / Element Plus** 政务后台  
- **信息密度高、布局紧凑**，避免大面积留白  
- 圆角 **≤ 4px**  
- **禁止：** 重阴影、渐变背景（业务区）、玻璃态、装饰性动画、过度拟物  
- **禁止：** emoji 图标、彩色填充图标、花哨 hover  

### 8.2 图标

- 统一 **线性图标**（Remix Icon 或 Element Plus Icons，或内联 SVG `currentColor`）  
- 颜色与主色/中性色一致  

### 8.3 建议 Token

```text
--color-primary: #1677FF
--color-success: #52C41A
--color-danger: #FF4D4F
--color-warning: #FAAD14
--color-border: #D9D9D9
--color-bg: #F0F2F5
--color-bg-elevated: #FFFFFF
--radius: 2px（且 ≤4px）
--control-height: 32px
--font-size: 14px
```

H5 信息架构可参考浙里办「办事路径」，**视觉仍服从本节政务后台规范**（线性图标宫格，非彩色运营风）。

### 8.4 PC 列表页（严格对照现网截图）

- 白底筛选区：多条件 + **查询（蓝实心）** + **重置（线框）**  
- **+ 新增（绿实心）**；次要操作为蓝实心  
- 表头 **浅蓝色** 背景  
- 操作列：**查看 / 编辑 / 删除** 蓝色文字链  
- 底部分页：共 N 条、每页条数、页码、前往  

### 8.5 PC 新增/编辑/查看（严格对照现网截图）

- **右侧全高抽屉（Drawer）**，非居中大弹窗；左侧列表区遮罩变暗  
- 顶栏左侧标题；右侧：  
  - 新增/编辑：**提交**（蓝实心）+ **关闭**（浅红/粉线框）  
  - 查看：仅 **关闭**  
- 表单：左侧 **分组标题**（基本信息等）+ **两列**字段；长字段通栏  
- 必填标签前红色 `*`  
- 控件高约 32px、细边框、圆角 ≤4px；只读浅灰底  
- 删除/危险确认：可用 **居中小对话框**（与业务抽屉区分）  

### 8.6 H5 组件

- 宫格：线性图标 + 短标题  
- 列表卡片：白底细边框、圆角 ≤4px  
- 帮扶步骤条：见 §7.2  
- 主按钮实心主色，次按钮线框

## 9. 交互原则

- 可点必有反馈（toast / 确认）  
- 危险操作二次确认  
- 表单必填校验  
- 空态有说明  
- 无权限操作不展示或置灰并提示  
- 跨端写入后另一端刷新或重新进入可见

## 10. 演示剧本（验收优先）

1. **活动：** PC 发布 → H5 报名 → PC 名单  
2. **建议：** PC 开征集 → H5 提交 → PC 受理办结 → H5 进度  
3. **帮扶：** H5 提交 → 中心受理指派/不予受理 → 部门审核或退回 → H5 四步进度卡  
4. **议事：** PC 发议题并开表决 → H5 讨论+投票 → PC 结果  
5. **权限：** 切换市级/村社，编辑按钮差异  
6. **服务资源：** H5「服务」查设施；PC 修改后 H5 详情变化
